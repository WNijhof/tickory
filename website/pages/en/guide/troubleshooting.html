Troubleshooting

The most common messages and what to do about them. On the server, always start with the log. The messages of the app and the server are in Dutch; they are quoted here with a translation.

Look first

docker compose ps          # is the container running, and does it say (healthy)?
docker compose logs --tail 100

On start-up the server writes which address it listens on and which database it uses, and reports it when there are no accounts yet.

Signing in

“Incorrect username or password.”, although you are sure of the password
The account may be blocked: that deliberately gives the same message. Check with docker compose exec tickory node server/main.ts user list whether it says “(geblokkeerd)” (blocked) after it, and activate it with user enable. See Managing users.
“Too many failed attempts. Try again in … minutes.”
Wait until the fifteen minutes have passed. If it happens to everyone at once and there is a reverse proxy in front, set TRUST_PROXY=1; see HTTPS.
The password of the only administrator is lost
Set a new password from the server: docker compose exec -it tickory node server/main.ts user passwd <name>.
There is not a single account yet
The log then says “Er zijn nog geen accounts” (there are no accounts yet). Put TODO_ADMIN_USER and TODO_ADMIN_PASSWORD in .env and run docker compose up -d, or create the account with user add <name> --admin.
The sign-in window keeps coming back
The session of that device has been revoked: the password was changed elsewhere, the device was signed out or the account was blocked. Sign in again.

The container does not start

“Het eerste account kon niet worden aangemaakt” (the first account could not be created)
The password in .env is shorter than 10 characters, the same as the username or too easy to guess (a common password, too few different characters), or the username contains characters that are not allowed. The reason follows it in the log. Change .env and start again.
“DEFAULT_TIMEZONE … is geen bekende tijdzone” (is not a known time zone)
The time zone in .env does not exist, for example because of a typo (Europa/Amsterdam instead of Europe/Amsterdam). Use a name from the list of time zones (IANA) and start again; without that setting Europe/Amsterdam applies.
The port is already in use
Something else on the server uses port 8787. In docker-compose.yml, change the first number of the ports line, for example "127.0.0.1:8790:8787", and use that number in the address and in your proxy.
docker compose pull says “denied” or “unauthorized”
The image is private and your server is not signed in to the registry. See Installing, or build the image yourself with build: ..
The container stays “unhealthy”
Look at the log. A damaged or unreadable database file is one possible cause; restore a backup in that case.

In the app

The top right keeps saying “Offline”
The app cannot reach the server. Check whether the server is running and whether the address can be reached from this device (with Tailscale: is Tailscale switched on on this device?). Click the status to try again. Your changes are kept in the meantime.
“Sync failed”
The server or a proxy in between returned an error. Look at the log of Tickory and of your proxy.
A message “Couldn't …”
The server refused one change, usually because something was deleted or changed on another device in the meantime. The reason is in the message; the rest of your changes went through as usual.
On the phone it does not work offline, or installing is not offered
The address does not start with https://. See HTTPS.
After updating the server I do not see the new version
The app fetches a new version in the background. Close the app and open it again.
The app sometimes does not open without a connection, although it could before
The browser, or a network filter such as AdGuard, can erase the stored files of the app. The app fills them up again by itself as soon as you open it with a connection.
Uploading an attachment fails
Look at what it says by the file. Waiting for a connection means the app keeps trying by itself. Too large: the file is bigger than MAX_UPLOAD_MB of your server (25 MB by default). Storage full: delete an attachment, or the administrator raises ATTACHMENT_QUOTA_MB. If a large file keeps failing and the browser reports 413 or a broken connection, a reverse proxy is not letting it through: see Large files (nginx: client_max_body_size). Administrator: if nothing is in the log, check whether the disk is full (507).
An attachment has disappeared or cannot be opened
Did you restore a backup without the folder with attachments? Then the attachment is still in the list, but its file is missing: put the attachments folder back (see Backup).
A date is not recognised, or is recognised where it should not be
See Dates and recurrences. A ~ switches recognition off.
“Local storage isn't available”
The browser does not allow data to be stored, for example in a private window with strict settings. The app works, but keeps nothing when you close the window.

Notifications do not arrive

This is about notifications in the browser. The Android app schedules its alarms itself; look under and at the problems screen there (see Android app). The whole picture is in Reminders.

There is no reminder, or it is at another time than you thought
First look in the task window to see whether the reminder is there, and whether the task has a time: a reminder before the task only exists for a task with a time. Also check your time zone under ; the times in the app and in the notification follow that time zone.
The button is missing, or the app says the browser cannot receive notifications
The address does not start with https:// (and is not localhost), or the browser has no push notifications. On an iPhone or iPad it only works in the app that you have put on the home screen. See HTTPS.
“”
You refused permission earlier. Tickory cannot undo that itself: allow notifications for the site in your browser's settings (usually through the padlock or the site information next to the address) and then choose again.
The device is registered, but the test notification does not come
Look under at this device: it shows the last error, or that nothing has been delivered yet. If the test says that no device is registered (“”), turn notifications on first. On a computer the operating system (do not disturb, focus mode) can hide the notification too.
The test fails with an error from the server
The server itself must be able to reach the outside world, namely the push services of Google, Mozilla, Microsoft and Apple. If outgoing traffic is blocked, allow it. Look at the log as well. A device that no longer exists at the push service is forgotten by the server by itself; turn notifications on again then.
Only Safari on an iPhone or iPad gives trouble
Apple's push service asks for a contact address. Put VAPID_SUBJECT in .env and restart the container; see Reminders, for administrators.
Notifications come late, or an old reminder never came
The server looks every 20 seconds. If the server or the device was off, whatever is at most an hour late is still sent; anything older lapses.
No notifications after restoring a backup or starting with an empty database
The keys for notifications belong to the database. If you start with a new one, new keys apply: open the app again on each device so that it registers again by itself, or turn notifications on again.
Only one of your devices gets notifications
Notifications are turned on per device and per browser. Turn them on on every device where you want them. A blocked account or a signed-out device gets none any more.

After restoring a backup

Do devices show tasks that should no longer be there, or is something missing? Sign out and in again on every device. See Backup and restore.

If you cannot work it out

Search the issues on GitHub or open a new one. Mention the version, how you run Tickory (Docker or bare, with which proxy), what you did, what you expected and what happened, and the relevant lines from the log. Do not include passwords or other secrets. If you think you have found a security vulnerability, do not report it publicly but through “Report a vulnerability” on GitHub.
