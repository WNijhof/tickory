Backup and restore

Everything is in one SQLite file in the Docker volume. A backup is a copy of that file, made with a command that also works while the app is in use.

Making a backup

docker compose exec -T tickory node server/backup.ts /data/backups/todo-$(date +%F).db

This makes a complete, consistent copy with today's date in its name, for example todo-2026-11-17.db.

  • The command never overwrites an existing file. If you run it twice on one day, the second time fails; give a different name in that case.
  • The name has to end in .db.
  • Do not simply copy the database file with cp while the app is running: such a copy can be incomplete. Use the command above.

Attachments are included

The attachments are not in the database but files in the attachments/ folder of your data volume. The same command copies them along: next to todo-2026-11-17.db comes a folder todo-2026-11-17.attachments/ with the files of the attachments that are in that copy. That way the database and the files belong together; a file that was deleted between the two steps is skipped and reported. Get both off the server. Count on extra storage: the size of your attachments comes on top, and the copy contains everything users have uploaded, so keep it as carefully as the database.

Getting the copy off the server

The copies are in the same volume as the database itself. If the disk fails, you lose both. So get them off the server regularly:

docker cp tickory:/data/backups ./backups

and put the directory backups somewhere else: on another computer, an external disk, or encrypted with a storage service. You clean up old copies yourself; they are not removed automatically.

Keep a backup the way you keep the database

A copy contains all tasks of all users, the password hashes, the (hashed) sessions and the server's keys for notifications: the private key (VAPID) and the secret that signs the buttons in a notification. Whoever has it can use those buttons to complete or postpone any task of any user. Do not leave it where others can get at it, not even in a folder that other users of the server can read.

Automatically, every night

Schedule the command with cron on the server (crontab -e). This example makes a copy every night at 3 o'clock; change the path to the directory that holds your docker-compose.yml. In a crontab a percent sign is written as \%.

0 3 * * * cd /path/to/tickory && docker compose exec -T tickory node server/backup.ts /data/backups/todo-$(date +\%F).db

Restoring a backup

The app has to be stopped for this. Put the file you want to restore as backup.db in the directory where you run the commands.

docker compose down
docker run --rm -v tickory_tickory-data:/data -v "$PWD":/backup alpine sh -c \
  "rm -f /data/todo.db-wal /data/todo.db-shm && cp /backup/backup.db /data/todo.db && chown 1000:1000 /data/todo.db"
docker compose up -d
  • The name of the volume starts with the name of the directory in which you run docker compose; here that is tickory, so tickory_tickory-data. Check the name with docker volume ls.
  • The command replaces the database with your copy and sets the owner, so that the app can write to it.

If you also restore the attachments, copy the folder todo-2026-11-17.attachments back to /data/attachments of the volume, for example in the same command (cp -r /backup/todo-2026-11-17.attachments/. /data/attachments/, then chown -R 1000:1000 /data/attachments). At start-up the server checks that the database and the files fit together: files without an attachment are cleaned up, and an attachment whose file is missing (because you did not restore the folder) is reported in the log and stays in the list, but cannot be opened.

After that: sign in again on every device

After restoring, sign out and in again on every device (, then ). A device that knew newer changes than the backup only notices the restored file by itself as long as the server has not yet grown past that device's state. Signing in again is the sure way, and it costs nothing: everything is on the server.

Whatever was added or changed after the backup was made is gone after restoring.

Without Docker

The command is the same, without the Docker part:

node server/backup.ts ./backups/todo-$(date +%F).db

The source is the file from DB_PATH (./data/todo.db by default). You restore by stopping the server, removing the files todo.db-wal and todo.db-shm next to the database, putting your copy in the place of todo.db and starting the server again.
