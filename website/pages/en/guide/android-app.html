Android app

The Android app shows the web app of your own server in an app of its own and schedules your reminders as alarms on the phone itself. So they also go off when the app is closed and when your phone has no internet.

No download yet

There is no released APK yet. The first APK comes with the next version of Tickory, as a file attached to that version on the releases page on GitHub. Until then you use the web app in your phone's browser, or you build the app yourself; see building it yourself.

What the app is

  • An app of its own, written in Kotlin, that shows your Tickory server in Android's built-in browser (Android System WebView). It is the same app as in your browser, with the same screens.
  • On top of that the app fetches your tasks and reminders and sets them as alarms on the device. A reminder goes off without the server or a push service being involved.
  • No Google services: no Google Play, no Firebase, no trackers or statistics. The app only talks to the server you enter. The built-in browser sends no usage statistics to Google and does not use Safe Browsing.
  • The sign-in the app itself uses in the background is stored encrypted on the device (key in the Android Keystore). The web app inside the app keeps its own copy of the sign-in, like any browser does, in the app's private storage and not encrypted; whoever roots the device or can read the app's data can read that one too. Nothing from the app goes into cloud backups or when transferring to another device.

You need Android 8 or newer. The app follows the language of the device (Dutch or English; any other language gets Dutch), and the web app inside it follows its own language choice.

Honest about the status

The app has been tested on a computer: the calculation rules (also around summer and winter time), a simulated Android with alarms, notifications, buttons and screens, and one test against a real server. The maker has not yet tried it on a real phone. That is the first thing that has to happen; if you notice something on a device, please report it on GitHub.

Installing

As soon as there is an APK:

  1. Download the file tickory-<version>.apk from the releases page on the phone.
  2. Open the file. The first time, Android asks whether the app you open it with (your browser or file manager) may install unknown apps. Allow that and go back. You only have to do this once.
  3. Open Tickory, enter the address of your server and sign in.
  4. Allow notifications if the app asks.

Android does not check an APK from outside Google Play for you. So only download it from the releases page of the repository itself.

The address of your server

The first time, the app asks for the address you open Tickory with in the browser, for example https://tasks.example.org or, on your home network, http://192.168.1.10:8787.

  • If you do not type http:// or https://, the app assumes https. It drops a path after the address and the port 443 or 80.
  • Do not put a username or password in the address; you sign in afterwards, in the app.
  • The app only saves the address once the server answers like a Tickory server should (the address /health). If it is something else or nothing, it says so, with a tip: the address does not exist, the server is not running, the certificate is not trusted, or the address redirects to another address (the app only opens the address you enter).
  • https is the recommended choice and required for a server on the internet. With http:// the connection is not encrypted; the app only allows that for an address on your own network (such as 192.168.1.10 or nas.local) and warns you when you enter such an address. It refuses an http:// address for a server on the internet, even if it was set in an earlier version; change the server address then and use https://.
  • You can change the address later: the app asks for confirmation, because you are signed out, the scheduled alarms disappear and changes that have not been sent to the server yet are lost.

Permissions, and why

PermissionWhat for
InternetReaching the server.
Notifications (Android 13 and newer; the app asks for it)Showing the reminders. Without this permission you do not see them.
Exact alarmsMaking a reminder go off on the minute, also in sleep mode. On Android 13 and newer this is always on. On Android 12 you can turn it off; the reminder then sometimes arrives a few minutes late.
Starting after bootAndroid erases alarms when the phone is switched off; the app sets them again after boot (also after a time zone change, a changed clock or an update of the app).
Nearby devices (Android 17 and newer only; the app asks for it)Android 17 only lets an app reach addresses on your home network after this permission. The app only asks for it if your server is at home (such as 192.168.… or nas.local) and only uses it to reach that server.
Network state and staying awakeFor refreshing in the background: only with a connection, and finishing the work before the device sleeps again.

The app asks for no access to location, contacts, files, camera or microphone.

Widgets

With the next version the app gets home screen widgets: Today, Project or list, Upcoming and an Add task button, with completing from the home screen, also without internet. See Widgets on Android. The version that is out now does not have them yet.

Share to Tickory

In the share menu of other apps (browser, messages, maps) you will find Tickory. Tap it and the Add task window opens, already filled in: the title of the page or the first line of the text becomes the task title, and the rest (for example the link) the description. The task goes to your Inbox. Nothing is created until you tap Add, so you can still change the title, the project or the date, or cancel.

Reminders in the app

You set the reminders as in the browser; see Reminders. The app refreshes your data right after signing in, right after a change to a task or reminder, then every quarter of an hour (with a connection) and every time you open it.

  • The notification has the buttons and . brings the same notification back ten minutes later. If the phone has no connection, the app remembers and ticks the task off as soon as it can (for three days; after that it gives up and says so).
  • If you tap the notification, the app opens at that task.
  • What is at most an hour late (the phone was off) is still shown; anything older is not. The app schedules at most 200 reminders, up to 30 days ahead; that window moves along with every refresh.

When the notifications do not arrive

In the app open and choose . Under you see what is not right yet, with a button to the right Android setting:

  • Notifications are off for Tickory (). Turn them on, including the channel Reminders, in Android's settings under Apps, Tickory, Notifications.
  • Exact alarms are off (Android 12 only): turn on Alarms & reminders for Tickory.
  • Battery saver is on for Tickory (). Choose Unrestricted. Some brands (Xiaomi, Huawei, OnePlus, Samsung) shut down background apps extra strictly; also look for Autostart or Sleeping apps and take Tickory out of those.
  • After Force stop, Android passes nothing on until you open the app again.
  • Do not disturb or a silent profile stops the sound; the notification is still there.

If everything is right you see , with the version number of the app below it.

Limitations

  • Opening without a connection only works with https. The web app stores itself with a service worker and browsers only allow that on https. With an http:// address the app therefore does not open away from home; the reminders do go off.
  • Only certificates that Android itself trusts (such as those from Let's Encrypt). A self-made or self-added certificate is not accepted.
  • A sign-in page in front of your server (Authelia, Cloudflare Access and the like) does not work: the app only opens the address that is set and then cannot reach /health and /api/.
  • No file picker in the app. Tickory currently has no attachments or other parts that ask for a file, so you will not notice this.
  • A notification does not replace the web app: a reminder is an alarm of the phone. On a device without Android System WebView (or with WebView turned off) the app does not start; it says so.

Updating

Install the new APK over the old one; your data stays. Android only updates an app if the new APK is signed with the same key as the old one.

  • APKs from the releases page are signed with the maker's key and can succeed each other. That holds once the maker has set up that key in GitHub; without a key, GitHub builds a debug APK.
  • A debug APK cannot update an earlier version (every build has a different throwaway key): remove the old app first. The same goes for an APK you build yourself with assembleDebug on another computer.
  • In the app, look under to see which version you have.

Building it yourself

Would you rather not wait for the first release? You need JDK 21 (17 or newer works) and the Android SDK; Gradle comes along by itself. The full instructions, the chosen versions and signing with your own key are in android/README.md (in Dutch).

cd android
./gradlew assembleDebug     # app/build/outputs/apk/debug/tickory-debug.apk

Put the file on your phone and install it as above. That debug APK is for trying out; if you want to keep using it and be able to update it, sign it with a key of your own (assembleRelease) and keep that key safe: whoever loses it has to remove the app and install it again.
