Managing users

An administrator creates the accounts and resets passwords. That can be done in the app, and also from the server when you can no longer get into the app.

How accounts work

  • There is no open sign-up and no password reset by e-mail. Tickory does not send e-mail.
  • The first account (from .env, see Installing) is an administrator. You can appoint more administrators.
  • Every account has its own Inbox and only sees the projects it is a member of.
  • An administrator manages accounts, not tasks. An administrator, too, only sees the projects they are a member of themselves.
  • There is always at least one active administrator: you cannot block the last one or take away their administrator rights.

Creating an account

  1. Open .
  2. Fill in a username, a name and an initial password. Tick if this account may manage accounts as well.
  3. Choose and pass the username and the initial password on to the person. They can change the password themselves afterwards.

From the server

The same actions as commands, for example when you have lost the password of the only administrator. Run them in the directory with docker-compose.yml, while the container is running.

docker compose exec tickory node server/main.ts user list
docker compose exec -e TODO_PASSWORD='a-good-password' tickory node server/main.ts user add anna --name "Anna de Vries"
docker compose exec -it tickory node server/main.ts user passwd anna        # asks for the password, hidden
docker compose exec tickory node server/main.ts user disable anna
docker compose exec tickory node server/main.ts user enable anna
docker compose exec tickory node server/main.ts user logout-all anna
docker compose exec tickory node server/main.ts user reset-2fa anna
CommandWhat it does
user listShows all accounts: username, name, administrator or user (the command prints these as beheerder and gebruiker), and whether the account is blocked (geblokkeerd).
user add <name>Creates an account. With --name "Full name" you give the name others see, with --admin you create an administrator.
user passwd <name>Sets a new password and signs out all devices of that user.
user disable <name>Blocks the account and signs it out everywhere.
user enable <name>Makes a blocked account active again.
user logout-all <name>Signs out all devices of that user, without changing the password.
user reset-2fa <name>Turns off two-step verification for that user, for example for the only administrator who lost both phone and recovery codes.

Passing the password. user add and user passwd need a password. You give it in one of two ways:

  • with -e TODO_PASSWORD='…', as in the example for user add;
  • or with -it, as for user passwd: the command then asks for the password twice, without showing it.

Without TODO_PASSWORD and without -it no password can be asked for, and the command stops with an error. The messages of these commands are in Dutch.

If you run without Docker, leave out docker compose exec tickory: node server/main.ts user list.

Rules for names and passwords

  • Username: 2 to 40 characters; letters, digits, dot, hyphen and underscore; the first character is a letter or digit. Capitals make no difference: Anna and anna are the same account. A username cannot be changed afterwards.
  • Name: 1 to 100 characters. This is what others see in shared projects.
  • Password: at least 10 characters, not the same as the username and not easy to guess: at least 5 different characters, no common word or password (not even with digits after it), no short repetition and no sequence of only digits. A long phrase works well.

Protection against guessing

Signing in is limited per fifteen minutes: after eight failed attempts on one username from the same address, after forty from the same address (an IPv6 network counts as one address) or after sixty on one username in total, the server refuses further attempts until those fifteen minutes have passed. An attempt is counted before the password is checked, so a hundred attempts at once do not get through. Because the counter for a username is per address, someone else cannot lock you out of your account from their own address. The counters are kept in memory: restarting the server clears them. If the server is busy checking passwords, a sign-in attempt gets “De server is druk” (the server is busy, 503); trying again a moment later helps.

Guessing the current password when changing a password is limited too (five wrong attempts per fifteen minutes). Every user also has limits on what can be stored: for example 10,000 tasks per project, 500 labels, 5,000 reminders and 20 signed-in devices (the longest unused one is signed out at the next sign-in). The full list is in SPEC.md (chapter 4a) and in server/limits.ts; the app tells you when you reach a limit.

If there is a reverse proxy in front of Tickory, set TRUST_PROXY=1. Otherwise all visitors seem to come from the same address (that of the proxy) and one person with many wrong attempts can block signing in for everyone. See HTTPS.
