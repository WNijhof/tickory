Installing with Docker

Tickory runs as a single container: the server and the web app together. The data lives in one SQLite file in a Docker volume.

What you need

  • A computer that stays on: a mini PC, a NAS, a Raspberry Pi or a server.
  • Docker with docker compose, and git to get the files.
  • A processor the image exists for: amd64 (ordinary PC, mini PC, most NAS systems) or arm64 (Raspberry Pi with a 64-bit system). A 32-bit system is not supported.

Installing

1. Get the files

git clone {{repo}}.git
cd tickory
cp .env.example .env

2. Choose the first account

Open .env and fill in a username and a password. (The comments in that file are in Dutch.)

TODO_ADMIN_USER=anna
TODO_ADMIN_PASSWORD=choose-a-long-password-here
# The name as others see it (optional; otherwise the username):
TODO_ADMIN_NAME=Anna de Vries
  • The password has at least 10 characters, may not be the same as the username and may not be easy to guess: no common word or password, not too few different characters. A long phrase works well.
  • This account is created on the very first start and is an administrator. You then use it to create the other accounts in the app; see Managing users.
  • Once an account exists, these lines no longer do anything. After the first start, remove the password from .env and recreate the container (docker compose up -d --force-recreate): otherwise it stays in the container's configuration, where docker inspect shows it.
  • Would you rather not have it in the environment at all? Set TODO_ADMIN_PASSWORD_FILE to the path (inside the container) of a file with the password, for example a Docker secret under /run/secrets/, and leave out TODO_ADMIN_PASSWORD.
  • Never put .env in git. It is already listed in .gitignore.

3. Start

docker compose up -d
docker compose ps          # after a few seconds: (healthy)
docker compose logs -f     # follow the log; stop with Ctrl+C

The log says “Eerste account … (beheerder) aangemaakt” (first account, administrator, created) and then on which address Tickory listens. Open http://127.0.0.1:8787 in a browser on the server itself and sign in.

Making it reachable for other devices

As configured in docker-compose.yml, Tickory is only reachable from the server itself (127.0.0.1:8787). That is on purpose: it makes you put HTTPS in front of it first.

  • Recommended: HTTPS. Needed for phones (working offline and installing as an app). See HTTPS: with Tailscale nothing has to become public.
  • At home only, without HTTPS: in docker-compose.yml, change the line "127.0.0.1:8787:8787" to "8787:8787", run docker compose up -d and open http://<ip-of-the-server>:8787. The app then works in the browser of every device in the house, but not offline and not as an installed app.
Do not

Do not put Tickory on the open internet without HTTPS. Your password and your session would travel unencrypted.

The compose file

This is the docker-compose.yml from the repository, shown here without the (Dutch) comments it contains:

image or build
By default Docker pulls the ready-made image {{image}}:latest. If you would rather build on the server yourself, remove the line image: and put build: . in its place.
volumes
The database is in the volume tickory-data, inside the container under /data. So your data is kept when you replace the container.
read_only, cap_drop, no-new-privileges
Extra hardening: the container can only write in /data, runs as an ordinary user and has no special privileges.

Settings

Settings are passed as environment variables. With Docker you put them in .env.

VariableMeaning
TODO_ADMIN_USER
TODO_ADMIN_PASSWORD (or TODO_ADMIN_PASSWORD_FILE)
TODO_ADMIN_NAME		The first account. Only used as long as not a single account exists.
TRUST_PROXYSet to 1 when your own reverse proxy is in front. See HTTPS.
VAPID_SUBJECTOptional: your contact address for the browser's push service (mailto:you@example.org or an https address), for notifications. See Reminders.
DEFAULT_TIMEZONEThe time zone for users who have not set one themselves; Europe/Amsterdam by default.
PORTThe port the server listens on; 8787 by default.
HOSTThe address the server listens on; 127.0.0.1 by default, 0.0.0.0 in the container.
DB_PATHWhere the database is; ./data/todo.db by default, /data/todo.db in the container.
CORS_ORIGINOptional: one exact address that may call the server from another origin. Normally not needed.

The supplied docker-compose.yml passes the first account, TRUST_PROXY, VAPID_SUBJECT and DEFAULT_TIMEZONE on from .env. PORT, HOST and DB_PATH already have the right value in the container; if you want to use CORS_ORIGIN, add it yourself under environment:.

The image is still private

As long as the repository and the image are private on GitHub, your server has to sign in once to be able to fetch them:

docker login ghcr.io -u <your-github-name>     # password: a token with only "read:packages"

Once they are public, this is not needed.

Without Docker

Handy for trying it out or for development. You only need Node 26; there are no packages to install and there is no build step.

TODO_ADMIN_USER=anna TODO_ADMIN_PASSWORD='a-good-password' node server/main.ts

Then open http://127.0.0.1:8787. On Windows you double-click start.cmd (or run .\start.cmd in PowerShell): the first time it asks for a username and a password for the first account, and then the server starts.

And after that

  • Set up HTTPS, so that it works on phones too.
  • Create accounts for the others.
  • Schedule a backup.
