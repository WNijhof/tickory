Installeren met Docker

Tickory draait als één container: de server en de web-app samen. De gegevens staan in één SQLite-bestand in een Docker-volume.

Wat je nodig hebt

  • Een computer die aan blijft staan: een mini-pc, een NAS, een Raspberry Pi of een server.
  • Docker met docker compose, en git om de bestanden op te halen.
  • Een processor waarvoor de image bestaat: amd64 (gewone pc, mini-pc, de meeste NAS-systemen) of arm64 (Raspberry Pi met een 64-bit systeem). Een 32-bit systeem wordt niet ondersteund.

Installeren

1. Haal de bestanden op

git clone {{repo}}.git
cd tickory
cp .env.example .env

2. Kies het eerste account

Open .env en vul een gebruikersnaam en een wachtwoord in:

TODO_ADMIN_USER=anna
TODO_ADMIN_PASSWORD=kies-hier-een-lang-wachtwoord
# De naam zoals anderen die zien (optioneel; anders de gebruikersnaam):
TODO_ADMIN_NAME=Anna de Vries
  • Het wachtwoord heeft minimaal 10 tekens en mag niet gelijk zijn aan de gebruikersnaam.
  • Dit account wordt bij de allereerste start aangemaakt en is beheerder. Daarmee maak je daarna in de app de andere accounts aan; zie Gebruikers beheren.
  • Bestaat er al een account, dan doen deze regels niets meer. Na de eerste start kun je het wachtwoord dus uit .env halen.
  • Zet .env nooit in git. Het staat al in .gitignore.

3. Start

docker compose up -d
docker compose ps          # na enkele seconden: (healthy)
docker compose logs -f     # het logboek volgen; stoppen met Ctrl+C

In het logboek staat “Eerste account … (beheerder) aangemaakt” en daarna op welk adres Tickory luistert. Open http://127.0.0.1:8787 in een browser op de server zelf en log in.

Bereikbaar maken voor andere apparaten

Zoals het in docker-compose.yml staat, is Tickory alleen bereikbaar vanaf de server zelf (127.0.0.1:8787). Dat is met opzet: zo zet je er eerst HTTPS voor.

  • Aanbevolen: HTTPS. Nodig voor telefoons (offline werken en installeren als app). Zie HTTPS: met Tailscale hoeft er niets openbaar te worden.
  • Alleen thuis, zonder HTTPS: verander in docker-compose.yml de regel "127.0.0.1:8787:8787" in "8787:8787", draai docker compose up -d en open http://<ip-van-de-server>:8787. De app werkt dan in de browser van elk apparaat in huis, maar niet offline en niet als geïnstalleerde app.
Niet doen

Zet Tickory niet zonder HTTPS op het open internet. Je wachtwoord en je aanmelding gaan dan onversleuteld over de lijn.

Het compose-bestand

Dit is het docker-compose.yml uit de repo, hier zonder de toelichting die erin staat:

image of build
Standaard haalt Docker de kant-en-klare image {{image}}:latest op. Bouw je liever zelf op de server, haal dan de regel image: weg en zet er build: . voor in de plaats.
volumes
De database staat in het volume tickory-data, in de container onder /data. Je gegevens blijven dus bewaard als je de container vervangt.
read_only, cap_drop, no-new-privileges
Extra afscherming: de container kan alleen in /data schrijven, draait als een gewone gebruiker en heeft geen bijzondere rechten.

Instellingen

Instellingen geef je mee als omgevingsvariabelen. Met Docker zet je ze in .env.

VariabeleBetekenis
TODO_ADMIN_USER
TODO_ADMIN_PASSWORD
TODO_ADMIN_NAME		Het eerste account. Alleen gebruikt zolang er nog geen enkel account bestaat.
TRUST_PROXYZet op 1 als er een eigen reverse proxy voor staat. Zie HTTPS.
PORTDe poort waarop de server luistert; standaard 8787.
HOSTHet adres waarop de server luistert; standaard 127.0.0.1, in de container 0.0.0.0.
DB_PATHWaar de database staat; standaard ./data/todo.db, in de container /data/todo.db.
CORS_ORIGINOptioneel: één exact adres dat de server vanaf een andere herkomst mag aanroepen. Normaal niet nodig.

Het meegeleverde docker-compose.yml geeft alleen het eerste account en TRUST_PROXY door uit .env. PORT, HOST en DB_PATH hebben in de container al de juiste waarde; wil je CORS_ORIGIN gebruiken, dan voeg je die zelf toe onder environment:.

De image is nog privé

Zolang de repo en de image op GitHub privé staan, moet je server één keer inloggen om ze te kunnen ophalen:

docker login ghcr.io -u <jouw-github-naam>     # wachtwoord: een token met alleen "read:packages"

Staan ze openbaar, dan is dit niet nodig.

Zonder Docker

Handig om te proberen of mee te ontwikkelen. Je hebt alleen Node 26 nodig; er zijn geen pakketten om te installeren en er is geen build-stap.

TODO_ADMIN_USER=anna TODO_ADMIN_PASSWORD='een-goed-wachtwoord' node server/main.ts

Open daarna http://127.0.0.1:8787. Op Windows dubbelklik je op start.cmd (of draai .\start.cmd in PowerShell): bij de eerste keer vraagt dat om een gebruikersnaam en een wachtwoord voor het eerste account, en daarna start de server.

En daarna

  • HTTPS regelen, zodat het ook op telefoons werkt.
  • Accounts aanmaken voor de anderen.
  • Een back-up inplannen.
