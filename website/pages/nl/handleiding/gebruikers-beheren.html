Gebruikers beheren

Een beheerder maakt de accounts aan en herstelt wachtwoorden. Dat kan in de app, en ook vanaf de server als je er in de app niet meer in komt.

Hoe accounts werken

  • Er is geen open registratie en geen wachtwoordherstel per e-mail. Tickory verstuurt geen e-mail.
  • Het eerste account (uit .env, zie Installeren) is beheerder. Je kunt meer beheerders aanwijzen.
  • Elk account heeft een eigen Inbox en ziet alleen de projecten waar het lid van is.
  • Een beheerder beheert accounts, geen taken. Ook een beheerder ziet alleen de projecten waar die zelf lid van is.
  • Er blijft altijd minstens één actieve beheerder: de laatste kun je niet blokkeren of zijn beheerdersrechten afnemen.

In de app

Klik onderaan de zijbalk op je naam, kies Account, wachtwoord en apparaten en dan Gebruikersbeheer. Die knop staat er alleen als je beheerder bent.

Gebruikersbeheer: alle accounts op de server, en daaronder het formulier voor een nieuw account.

Een account aanmaken

  1. Klap Nieuw account open.
  2. Vul een gebruikersnaam, een naam en een beginwachtwoord in. Vink Beheerder aan als dit account ook accounts mag beheren.
  3. Kies Account aanmaken en geef de gebruikersnaam en het beginwachtwoord door aan de persoon. Die kan het wachtwoord daarna zelf wijzigen.

Een account beheren

Kies Beheren achter een account:

Wachtwoord herstellen
Je stelt een nieuw wachtwoord in. De persoon wordt op alle apparaten afgemeld en logt opnieuw in met het nieuwe wachtwoord.
Account blokkeren
De persoon kan niet meer inloggen en is direct overal afgemeld. De gegevens blijven bewaard, en taken in gedeelde projecten blijven staan. Met Account weer activeren draai je het terug.
Beheerder maken of Beheerdersrechten afnemen
Maakt van een gewone gebruiker een beheerder, of andersom.

Jezelf blokkeren of je eigen beheerdersrechten afnemen kan niet. Een account helemaal verwijderen kan ook niet; blokkeren is het alternatief.

Vanaf de server

Dezelfde handelingen als opdracht, bijvoorbeeld als je het wachtwoord van de enige beheerder kwijt bent. Voer ze uit in de map met docker-compose.yml, terwijl de container draait.

docker compose exec tickory node server/main.ts user list
docker compose exec -e TODO_PASSWORD='een-goed-wachtwoord' tickory node server/main.ts user add anna --name "Anna de Vries"
docker compose exec -it tickory node server/main.ts user passwd anna        # vraagt om het wachtwoord, ongezien
docker compose exec tickory node server/main.ts user disable anna
docker compose exec tickory node server/main.ts user enable anna
docker compose exec tickory node server/main.ts user logout-all anna
OpdrachtWat het doet
user listToont alle accounts: gebruikersnaam, naam, beheerder of gebruiker, en of het account geblokkeerd is.
user add <naam>Maakt een account. Met --name "Volledige naam" geef je de naam die anderen zien, met --admin maak je een beheerder.
user passwd <naam>Zet een nieuw wachtwoord en meldt alle apparaten van die gebruiker af.
user disable <naam>Blokkeert het account en meldt het overal af.
user enable <naam>Maakt een geblokkeerd account weer actief.
user logout-all <naam>Meldt alle apparaten van die gebruiker af, zonder het wachtwoord te wijzigen.

Het wachtwoord meegeven. user add en user passwd hebben een wachtwoord nodig. Dat geef je op een van twee manieren:

  • met -e TODO_PASSWORD='…', zoals in het voorbeeld bij user add;
  • of met -it, zoals bij user passwd: de opdracht vraagt dan twee keer om het wachtwoord, zonder het te tonen.

Zonder TODO_PASSWORD en zonder -it kan er geen wachtwoord worden gevraagd en stopt de opdracht met een foutmelding.

Draai je zonder Docker, dan laat je docker compose exec tickory weg: node server/main.ts user list.

Regels voor namen en wachtwoorden

  • Gebruikersnaam: 2 tot 40 tekens; letters, cijfers, punt, streepje en underscore; het eerste teken is een letter of cijfer. Hoofdletters maken geen verschil: Anna en anna zijn hetzelfde account. Een gebruikersnaam is achteraf niet te wijzigen.
  • Naam: 1 tot 100 tekens. Dit is wat anderen zien in gedeelde projecten.
  • Wachtwoord: minimaal 10 tekens, en niet gelijk aan de gebruikersnaam. Verdere eisen zijn er niet; een lange zin werkt goed.

Bescherming tegen raden

Na acht mislukte inlogpogingen binnen een kwartier voor dezelfde gebruikersnaam, of veertig vanaf hetzelfde adres, weigert de server verdere pogingen tot dat kwartier voorbij is. De tellers staan in het geheugen: een herstart van de server wist ze.

Staat er een reverse proxy voor Tickory, zet dan TRUST_PROXY=1. Anders lijken alle bezoekers van hetzelfde adres te komen (dat van de proxy) en kan één persoon met veel foute pogingen het inloggen voor iedereen blokkeren. Zie HTTPS.
