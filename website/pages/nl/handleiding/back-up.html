Back-up en terugzetten

Alles staat in één SQLite-bestand in het Docker-volume, met de bijlagen in een map ernaast. Een back-up is een kopie daarvan, gemaakt terwijl de app in gebruik is: als beheerder download je hem in de app, of je maakt hem met een opdracht op de server.

Downloaden in de app

  1. Open en kies .
  2. Klap open en lees de waarschuwing.
  3. Vul je wachtwoord in (en een code uit je authenticator-app als je tweestapsverificatie gebruikt) en kies .

Je browser slaat één bestand op, tickory-backup-2026-11-17.tar, met daarin:

  • tickory.db: een complete, consistente kopie van de database;
  • attachments/: de bestanden van alle bijlagen in die kopie;
  • tickory-backup.json (wanneer gemaakt, hoeveel bijlagen) en LEESMIJ.txt (de stappen om terug te zetten).

Een tar-bestand is een gewoon archief zonder compressie: Linux, macOS en Windows 10 en nieuwer pakken het uit met tar -xf, en 7-Zip opent het ook. De server stuurt het in delen, zodat ook een grote back-up de server niet vol laat lopen. Je kunt hooguit vijf back-ups per uur downloaden, en elke download komt met je naam in het logboek van de server. In de Android-app kan het niet; open Tickory daarvoor in een browser.

Wat erin staat

De back-up bevat de taken en bijlagen van alle gebruikers, de wachtwoord-hashes, de privésleutel voor meldingen (VAPID) en het geheim van de knoppen in meldingen (HMAC). Bewaar hem net zo zorgvuldig als de server zelf. Het sleutelbestand voor tweestapsverificatie (secret.key) zit er bewust niet in: zo geeft een gestolen back-up de tweede stap niet weg. Bewaar er zelf een kopie van, apart van je back-ups; zie hieronder.

Met een opdracht op de server

Een back-up maken

docker compose exec -T tickory node server/backup.ts /data/backups/todo-$(date +%F).db

Dit maakt een complete, consistente kopie met de datum van vandaag in de naam, bijvoorbeeld todo-2026-11-17.db.

  • De opdracht overschrijft nooit een bestaand bestand. Draai je haar twee keer op één dag, dan mislukt de tweede keer; geef dan een andere naam op.
  • De naam moet op .db eindigen.
  • Kopieer het databasebestand niet gewoon met cp terwijl de app draait: zo'n kopie kan onvolledig zijn. Gebruik de opdracht hierboven.

De bijlagen gaan mee

De bijlagen staan niet in de database maar als bestanden in de map attachments/ van je datavolume. Dezelfde opdracht kopieert ze mee: naast todo-2026-11-17.db komt een map todo-2026-11-17.attachments/ met de bestanden van de bijlagen die in die kopie staan. Zo horen database en bestanden bij elkaar; een bestand dat tussen de twee stappen werd verwijderd, wordt overgeslagen en gemeld. Haal beide van de server af. Reken op extra opslag: de grootte van je bijlagen komt erbij, en de kopie bevat alles wat gebruikers hebben geüpload, dus bewaar hem net zo zorgvuldig als de database.

De kopie van de server halen

De kopieën staan in hetzelfde volume als de database zelf. Gaat de schijf stuk, dan ben je beide kwijt. Haal ze daarom regelmatig van de server af:

docker cp tickory:/data/backups ./backups

en zet de map backups ergens anders neer: op een andere computer, een externe schijf of versleuteld bij een opslagdienst. Oude kopieën ruim je zelf op; ze worden niet automatisch verwijderd.

Bewaar een back-up zoals de database zelf

Een kopie bevat alle taken van alle gebruikers, de wachtwoord-hashes, de (gehashte) aanmeldingen en de sleutels van de server voor meldingen: de privésleutel (VAPID) en het geheim waarmee de knoppen in een melding worden ondertekend. Wie haar heeft, kan met die knoppen elke taak van elke gebruiker afvinken of uitstellen. Leg haar niet neer waar anderen bij kunnen, ook niet in een map die voor andere gebruikers van de server leesbaar is.

Automatisch, elke nacht

Plan de opdracht in met cron op de server (crontab -e). Dit voorbeeld maakt elke nacht om 3 uur een kopie; pas het pad aan naar de map waar je docker-compose.yml staat. In een crontab schrijf je een procentteken als \%.

0 3 * * * cd /pad/naar/tickory && docker compose exec -T tickory node server/backup.ts /data/backups/todo-$(date +\%F).db

Een back-up terugzetten

De app moet daarbij stilstaan. Zet het bestand dat je wilt terugzetten als backup.db in de map waar je de opdrachten draait.

docker compose down
docker run --rm -v tickory_tickory-data:/data -v "$PWD":/backup alpine sh -c \
  "rm -f /data/todo.db-wal /data/todo.db-shm && cp /backup/backup.db /data/todo.db && chown 1000:1000 /data/todo.db"
docker compose up -d
  • De naam van het volume begint met de naam van de map waarin je docker compose draait; hier is dat tickory, dus tickory_tickory-data. Controleer de naam met docker volume ls.
  • De opdracht vervangt de database door je kopie en zet de eigenaar goed, zodat de app erin kan schrijven.

Zet je ook de bijlagen terug, kopieer dan de map todo-2026-11-17.attachments terug naar /data/attachments van het volume, bijvoorbeeld in dezelfde opdracht (cp -r /backup/todo-2026-11-17.attachments/. /data/attachments/, daarna chown -R 1000:1000 /data/attachments). Bij het opstarten controleert de server of database en bestanden bij elkaar passen: bestanden zonder bijlage worden opgeruimd, en een bijlage waarvan het bestand ontbreekt (omdat je de map niet terugzette) wordt gemeld in het logboek en blijft in de lijst staan, maar laat zich niet openen.

Een gedownloade back-up (tar) terugzetten

Zet het bestand in de map waar je de opdrachten draait, en pas de bestandsnaam aan:

docker compose down
mkdir herstel && tar -xf tickory-backup-2026-11-17.tar -C herstel
docker run --rm -v tickory_tickory-data:/data -v "$PWD/herstel":/herstel:ro alpine sh -c \
  "rm -f /data/todo.db-wal /data/todo.db-shm && cp /herstel/tickory.db /data/todo.db && rm -rf /data/attachments && cp -R /herstel/attachments /data/attachments && chown -R 1000:1000 /data/todo.db /data/attachments"
docker compose up -d

Dit vervangt de database én de map met bijlagen door die uit de back-up. Het sleutelbestand secret.key in het volume blijft staan. Zet je terug op een nieuwe server, kopieer dan ook je bewaarde secret.key naar /data/secret.key (met chown 1000:1000); zonder dat bestand werkt tweestapsverificatie niet meer en moet die per gebruiker worden uitgezet met user reset-2fa (zie Gebruikers beheren).

Daarna: op elk apparaat opnieuw aanmelden

Meld na het terugzetten op elk apparaat af en weer aan (, dan ). Een apparaat dat nieuwere wijzigingen kende dan de back-up, merkt het teruggezette bestand alleen vanzelf op zolang de server nog niet voorbij de stand van dat apparaat is gegroeid. Opnieuw aanmelden is de zekere weg, en het kost niets: alles staat op de server.

Wat na het maken van de back-up is toegevoegd of gewijzigd, is na het terugzetten weg.

Zonder Docker

De opdracht is dezelfde, zonder het Docker-deel:

node server/backup.ts ./backups/todo-$(date +%F).db

De bron is het bestand uit DB_PATH (standaard ./data/todo.db). Terugzetten doe je door de server te stoppen, de bestanden todo.db-wal en todo.db-shm naast de database te verwijderen, je kopie op de plek van todo.db te zetten en de server weer te starten.
